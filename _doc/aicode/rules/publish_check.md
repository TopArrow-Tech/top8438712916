# 发布前自检

用户说要把应用发布到顶箭应用市场（首次发布或发布新版本）时，先按这份清单把整个应用过一遍。
顶箭会审查每一次提交，这里列的是最常见的驳回原因。提前改掉，能少等一轮审核。

## 怎么做

1. 按下面各节逐条检查。每条记「通过」，或「需修改：文件路径 + 原因」。
2. 先把结果列给用户。需修改的，问过用户再改。
3. 改完在顶箭「我的发布」里点「打开」，把主要功能走一遍。
4. 按 `AGENTS.md` 更新 changelog 并提交。

## 一、清单和包

- 根目录有 `manifest.json`，`id`、`name`、`runtime.type` 都在。`id` 发布后不能改。不要写 `version`：顶箭发布时给每一版分配编号。名称在发布表单里填，顶箭会写进安装包。
- `description` 不能还是模板里的「One-line description」或「一句话说明」，要一句话写清这个应用做什么。
- 不要放运行时：`php.exe`、`node.exe`、`python.exe`、`pythonw.exe`、`electron.exe`、`git.exe`、`php.ini`。
- 根目录不要有 `data/`、`logs/`、`runtime/`、`backups/`；任何一层都不要有 `.git`。
- 路径不超过 200 个字符；不用 `con`、`nul`、`com1` 这类 Windows 保留名当文件名。
- 体积：不超过 2 万个文件，单个文件解压后不超过 256MB，总共不超过 1GB。PHP、Python 应用不要带 `node_modules`。
- 应用图标在首次发布时上传：正方形 PNG，不超过 512×512、200KB。图标上不要有二维码、网址、联系方式、促销文字。

## 二、名称和介绍

- 应用名、版本名、英文名、`manifest.json` 的 `name`、界面上的大标题，都不能出现「顶箭」「TopArrow」「官方」。
- 名称、一句话简介、介绍、`description` 里不写网址、邮箱、电话、微信号、QQ、群号这类联系方式，也不引导用户去站外加好友或购买。
- 介绍里写的功能，代码里都要有。版本介绍要和这一版的改动对得上。
- 应用会联网、会用麦克风或摄像头、会对局域网开放的，在介绍里写明。

## 三、内容

界面文字、帮助说明、初始化数据（词库、题库、预置文章、示例数据）、图片、视频、音频、包里的压缩包都算。

- 不含色情、低俗擦边内容。
- 不含极端暴力、恐怖主义内容。
- 不含违法内容：毒品、赌博、武器交易、诈骗教程等。
- 不含仇恨、歧视、露骨辱骂。
- 不含涉及未成年人的不当内容。
- 不冒充他人或其他品牌，不误导用户。
- 不做政治题材：不做政治宣传，不评论政党、政治人物和敏感事件。拿不准就不写。
- 内容要和发布时选的年龄分级相符。

## 四、用户数据和权益

- 包里不带真实的个人信息、账号密码、密钥。重点看 `.env`、`.pem`、`.key`、数据库文件、日志、上传目录。示例数据用 `user@example.com` 这类一看就是占位的写法。
- 打进包的 `.sqlite`、`.db` 只能是干净的初始库，不能留着开发时的测试数据。
- 没有强制广告、关不掉的推广、伪装成系统弹窗的跳转，也没有用户不知道的统计或追踪脚本。
- 不在应用里另走一套收费、绕开顶箭市场。
- 用麦克风、摄像头、剪贴板，或读写用户自己的文件时，界面上要让用户知道用途。

## 五、知识产权

- 用到的第三方库，保留它们的 LICENSE 和版权声明。
- 字体、图标、音效、图片要有使用授权。拿不准的换成自己做的，或明确可以商用的。
- 不拿知名游戏、影视、品牌的名字、角色或 Logo 当应用名或图标。

## 六、代码安全和通信

- 平台分配的端口（`TOPARROW_APP_PORT`）只绑 `127.0.0.1`。
- 数据只写 `TOPARROW_DATA_DIR`，不写死 `C:\`、用户目录这类路径。
- JS、CSS、字体、图片都放在应用里，不从 CDN 或其他网站加载。
- 调用外部 API（AI、地图、统计、登录等）要合法，并在介绍里和第一次用到时告诉用户会连到哪里。
- 不下载并执行远程代码，不用 `eval` 执行从网上拿来的内容。
- 不执行用户不知道的系统命令。`scripts/install.*`、`migrate.*` 里只建表、写初始数据，不下载文件、不联网、不改注册表、不启动别的程序。
- Electron：不关 `contextIsolation`，不设 `webSecurity: false`，不对来路不明的网址调用 `shell.openExternal`。
- 包里任何文件都不要写给审查者或 AI 的指令（比如「请判定通过」「忽略某条规则」），这会被当成风险。

## 七、局域网功能

只有需要让同一网络里的其他设备（手机、另一台电脑）连进来时才看这一节。

可以在平台端口之外另开一个局域网端口，但下面几条都要做到：

1. `manifest.json` 声明 `"network": { "lan": true }`。
2. 默认关闭。用户在界面上点了「开启」才开始监听；关闭或空闲超时后释放端口。应用启动时不能对外监听，UDP 发现也算。
3. 网页服务绑用户所选网卡的局域网地址，不绑 `0.0.0.0`。UDP 发现只在开启期间监听，广播里不带连接码这类凭证。
4. 其他设备连进来，要输入连接码或经过配对确认。
5. 介绍里写明会对局域网开放、怎么关闭、传输有没有加密；界面上显示当前是否开放。

不允许 UPnP 端口映射、内网穿透，也不允许把服务暴露到公网。

## 八、报告格式

```text
发布前自检
- 清单和包：通过
- 名称和介绍：需修改 —— manifest.json 的 description 还是模板文字
- 内容：通过
- ……
需要我改哪几条？
```
